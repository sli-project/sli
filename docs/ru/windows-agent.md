# Подключение агента Windows

[English version](../en/windows-agent.md) · [Руководства](README.md)

Используйте агент .NET для x64, который предоставляет сервер SLI. Проверьте
прямой доступ контроллера домена Windows к серверу по HTTPS.

## Регистрация агента

1. Войдите как владелец платформы или с правом `access.manage`. Пока агенты
   не зарегистрированы, нажмите **Добавить агента** на **Главной**. Кнопка также
   доступна в разделе **Агенты**.
2. Укажите HTTPS-адрес, доступный напрямую с Windows, например
   `https://sli.example.test:8443`, без `/app`. Имя или IP должны входить в
   сертификат сервера. Команда подключается без прокси и перенаправлений.
   Выберите от 1 до 100 компьютеров (по умолчанию 1).
   Оставьте управление аудитом включённым, чтобы SLI настроила аудит Windows
   на контроллере домена. При ошибке адреса выберите имя или IP из сообщения.
   Если форма не загрузила параметры или пакет, проверьте MSI и сертификат
   на сервере и откройте её снова.
3. Нажмите **Создать команду** и выполните скопированную строку в 64-разрядном
   PowerShell от имени администратора на контроллере домена. Интерфейс сохранит
   адрес. Строка содержит секретный ключ регистрации на один час. Он допускает
   по одной регистрации на компьютер в пределах выбранного числа. Передавайте
   её только администратору, который установит агент. По истечении срока или
   лимита создайте новую команду. Скрипт проверяет TLS и хеш MSI до установки.
   Для подписанного MSI он также проверяет Authenticode.

## Проверка первых данных

1. После запуска службы проверьте колонку **Последняя связь** в разделе
   **Агенты**.
2. Откройте **Состояние системы → Первый запуск** по адресу `/app/admin/status`
   и дождитесь отметки **Первые данные: получены в …**. Затем в таблице **Источники**
   проверьте колонку **Последние данные** своего компьютера. Отдельно проверьте
   отчёты AD и групповых политик. Для их снимков нужна подтверждённая область
   домена контроллера.
3. Чтобы проверить оповещения, откройте **Оповещения → Каналы**
   (`/app/notifications?tab=channels`), настройте канал и нажмите
   **Отправить проверку**. Убедитесь, что сообщение пришло.

## Создание команды с сервера Debian

На сервере `sudo sli-agent-command` использует сохранённый адрес. В примере
адрес задаётся только для текущей команды.

```sh
sudo sli-agent-command --server-url https://sli.example.test:8443 --count 1
```

Подставьте HTTPS-адрес своего сервера. Если адрес не сохранён, передавайте
`--server-url` при каждом вызове. `--count` принимает 1–100, а `--no-audit`
оставляет управление аудитом выключенным.

## Проверка загруженного MSI

Для отдельной проверки MSI используйте PowerShell на компьютере, который
доверяет CA сервера. Подставьте в URL HTTPS-адрес своего сервера.

```powershell
curl.exe -fsS -D - -o SliAgent.msi https://sli.example.test:8443/api/v1/agent/installer/SliAgent.msi
Get-FileHash .\SliAgent.msi -Algorithm SHA256
```

Сверьте выведенный заголовок `X-SLI-Package-SHA256` с хешем файла. Для первой
регистрации используйте созданную команду.

## Замена стандартной установки

Для плановой замены стандартной MSI-установки выпустите новую команду для этого
компьютера, затем снова проверьте связь и первые данные. Если для существующей
регистрации требуется одобрение владельца, получите его до замены. При сообщении
о нестандартном каталоге состояния, `agent.json` или оставшейся старой службе
сохраните настройки и состояние агента и устраните указанную причину перед
повтором. Держите под рукой прежний MSI. Если замена прервётся после его
удаления, он может понадобиться для восстановления службы Windows.

## Удаление агента

В Windows откройте **Установленные приложения** и удалите **SLI Agent .NET**.
Его служба называется `SLIAgentNet`. Запись **SLI Agent** относится к старому MSI.
Чтобы отозвать и регистрацию на сервере, откройте компьютер в разделе
**Агенты** и выберите **Отключить агента**.
